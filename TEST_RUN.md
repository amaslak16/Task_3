## Невыполненные проверки

1. **Отправка почты для восстановления пароля — failed.** Новый пользователь
   создаётся через API; через UI открывается восстановление, вводится его
   уникальная почта @example.com и нажимается «Восстановить».
   Ожидается маршрут /reset-password и форма нового пароля с кодом из письма
   (страница 2 приложенной API-документации). Фактически остаётся /forgot-password.
   В Chrome записан сетевой ответ POST /api/password-reset: HTTP 500 Internal
   Server Error, ответ text/html. Проблема воспроизвелась в обоих браузерах.
   Скриншоты и DOM приложены к Allure, сетевые ошибки — к Chrome.
2. **Подсветка и переключение видимости пароля — error в предусловии.**
   Форма нового пароля не открывается из-за предыдущей проблемы. Проверка
   реализована: исходное скрытое поле, показ с типом text и классом
   input_status_active, повторное скрытие с типом password и той же подсветкой.
   Её выполнение на форме сброса пока заблокировано. Фикстура сообщает
   PreparationError, а не успешный результат или skip. Реальное поведение
   этого поля на текущем стенде не подтверждено.

HTTP 500 — ответ сервера, а не ошибка DNS/соединения. В итоговых прогонах
ошибок подключения к приложению и API подготовки/очистки не было. Первоначальный
DNS-сбой ограниченного исполнительного окружения устранён запуском с сетевым
доступом; он не включён в результаты проверяемого поведения.

## Подтверждённое поведение

Все 6 проверок основного функционала, 5 проверок ленты, 3 проверки кабинета
и переход к восстановлению пароля прошли. Для заказов проверялись конкретные
номера, названия и ингредиенты; состояния «В работе» наблюдались в UI отдельной
вкладки до получения номера из подтверждения. Оба глобальных счётчика увеличились,
и созданные заказы появились среди готовых.

Каждый полный прогон создаёт 11 уникальных пользователей; в каждом браузере все 11
удалены, все финализаторы пользователей завершились успешно. Сбой восстановления
не мешает удалению пользователей. API удаления заказов не документирован,
поэтому созданные через UI заказы остаются на учебном стенде.

При диагностике устранены гонка чтения начального номера 9999, несовместимость
нативного drag-and-drop Firefox и ранние клики при исчезновении overlay.
Для Firefox из Snap фабрика автоматически выбирает бинарники установленного
пакета напрямую; это устраняет запрет Snap на завершение сервиса Selenium.
Оставшиеся процессы старых диагностических запусков очищены отдельно.
